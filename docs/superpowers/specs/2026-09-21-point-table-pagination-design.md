# 点位主列表分页与实时值设计

## 目标与范围

设备详情页的点位配置主列表支持列宽拖动、固定高度垂直滚动和服务端分页，并将实时值与更新时间合并到对应点位行。分页大小支持 10、20、50、100、200、500；页面每 2 秒只刷新当前页可见点位的实时值显示。

本次不改变点位采集方式、实时值存储方式和现有轮询协议，不引入前端框架或新依赖。

## 方案

采用现有点位分页接口与实时值接口分离的方案：

- `GET /api/v1/devices/:id/points` 继续负责搜索、类型筛选和分页，将 `limit` 最大值由 200 提高到 500。
- `GET /api/v1/devices/:id/values` 继续返回设备运行实例的实时值快照。
- 浏览器加载当前页点位后，以 `TagName` 将最近一次实时值快照合并到当前页行中。
- 后续实时值轮询只更新当前页已有行的实时值和更新时间单元格，不重新渲染点位配置，也不重复请求点位分页接口。

该方案沿用现有 API 边界，避免让数据库点位查询依赖运行时管理器，同时确保 500 条每页的上限明确可控。

## 页面结构与交互

主列表列为：TagName、类型、地址、数据类型、位、可写、实时值、更新时间、操作。原有独立实时值表删除。

表格放入固定最大高度的滚动容器：内容超过高度时显示垂直滚动条，表头在垂直滚动时保持可见。横向空间不足时允许容器横向滚动，避免压缩重要字段或隐藏实时值。

每个表头右侧提供列宽拖动柄。拖动期间设置对应列宽，并为各列保留合理最小宽度。拖动结束后，按稳定列标识将宽度保存到 `localStorage`；刷新页面或重新进入设备详情页时恢复。存储不可用或数据无效时使用默认列宽，不影响主列表使用。

分页区位于表格下方，包含：

- 上一页和下一页按钮；
- 当前页、总页数与总条数；
- 每页数量选择：10、20、50、100、200、500。

默认每页 20 条。搜索文本、寄存器类型或每页数量变化时回到第一页。搜索输入沿用即时筛选，并通过短延迟合并连续输入，减少无效请求。翻页请求进行期间禁用分页按钮，避免响应乱序覆盖；只有最新一次点位请求可更新列表。

新增、编辑、删除或 CSV 全量导入成功后重新请求当前筛选条件下的点位页。若删除导致当前页超出新的总页数，则自动回退到最后一个有效页并重新加载。

## 实时值刷新

页面保留 2 秒轮询。轮询设备摘要和实时值，不轮询点位配置列表。

实时值快照保存在页面内存中。点位页加载完成后立即使用最近快照填充当前页；实时值请求完成后，仅按当前页 `TagName` 更新实时值和更新时间单元格。没有快照、设备未运行或某个 TagName 没有值时显示 `--`。

翻页、搜索或筛选会改变当前页点位集合。旧请求即使稍后返回，也不得覆盖新页面；实时值更新仅作用于当前 DOM 中带有匹配 TagName 的行。

实时值继续按现有 HTML 转义规则展示，不将返回内容拼接为可执行标记。

## 后端与兼容性

点位列表接口的 `limit` 合法范围调整为 1 到 500，`offset` 语义不变，响应继续使用现有 `items` 和总数信息，不新增破坏性字段。

现有调用方使用 200 或更小的限制时行为不变。500 是页面允许的最大值，防止无边界查询。

## 错误处理

点位分页请求失败时保留当前列表并在页面通知区展示错误；分页控件恢复可操作状态。实时值刷新失败时保留最后一次成功值并展示现有错误通知，不清空点位配置。列宽持久化失败不阻断表格操作。

## 测试与验收

后端测试覆盖：

- `limit=500` 可正常请求；
- `limit=501`、非数字和非正数返回 `invalid_pagination`；
- `offset` 与搜索、类型筛选组合时总数和分页结果正确。

前端按现有项目约定进行人工验收：

- 六种分页大小均可选择，首尾页按钮状态和总数正确；
- 搜索、筛选和分页大小变化后回到第一页；
- 500 条数据时列表在固定区域内垂直滚动，表头保持可见；
- 各列可拖动且刷新页面后宽度恢复；
- 独立实时值表不再显示，当前页每行显示对应实时值和更新时间；
- 2 秒刷新不会重载点位页，不会改变滚动位置、分页状态或用户设置的列宽；
- 翻页后只显示并刷新新当前页的实时值；
- 新增、编辑、删除和导入后分页与实时值映射保持正确。
