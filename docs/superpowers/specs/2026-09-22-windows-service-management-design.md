# Windows 服务管理设计

## 目标

让 `modbus-scan.exe` 能直接安装和管理 Windows 服务，同时保留现有控制台运行与 CSV 离线校验能力。服务随系统自动启动，并在 Windows 服务控制管理器（SCM）要求停止或关机时复用现有的优雅退出流程。

## 范围

程序提供以下子命令：

- `install`：注册服务，启动类型为自动，并保存可执行文件及配置文件的绝对路径。
- `uninstall`：删除已停止的服务；服务仍在运行时返回明确错误，不隐式强制终止。
- `start`：启动已注册服务。
- `stop`：请求服务停止，并等待进入停止状态或超时。
- `restart`：先停止再启动；服务原本已停止时直接启动。
- `status`：输出稳定、适合人工读取的服务状态。

首版不支持自定义服务名、显示名、服务账户或启动类型。固定服务名为 `modbus-scan`，显示名为 `Modbus Scan`，使用 Windows 内置 `LocalSystem` 账户和自动启动类型。

## 命令行契约

控制台运行方式保持不变：

```powershell
.\modbus-scan.exe -config configs\config.toml
```

服务管理命令如下：

```powershell
.\modbus-scan.exe install -config D:\modbus-scan\configs\config.toml
.\modbus-scan.exe start
.\modbus-scan.exe status
.\modbus-scan.exe stop
.\modbus-scan.exe restart
.\modbus-scan.exe uninstall
```

`install` 的 `-config` 默认值仍为 `configs/config.toml`。安装前将可执行文件路径和配置文件路径转换为绝对路径，并确认配置文件可读取且内容有效。SCM 中保存的启动参数只包含服务运行所需的 `-config <absolute-path>`。路径由 Windows API/库正确引用，不自行拼接易出错的命令行字符串。

未知子命令、子命令不支持的参数或缺少参数时返回非零退出码并显示用法。`-validate -csv` 仍是无子命令的离线模式，不允许作为服务管理子命令参数。

## 架构

采用已有间接依赖 `golang.org/x/sys/windows/svc` 及其管理能力，原生对接 SCM，不新增第三方模块。

Windows 专属代码使用 `//go:build windows` 隔离，负责：

- 判断当前进程是否由 SCM 启动。
- 实现 SCM 服务执行器，接收停止和系统关机控制请求。
- 安装、卸载、启动、停止、重启和查询服务。
- 将 Windows 原生服务状态映射为稳定的应用状态文本。

平台无关的入口代码负责：

- 解析顶层运行模式和子命令。
- 调用服务管理抽象或现有应用运行函数。
- 统一错误包装和退出码。

非 Windows 构建提供小型兼容实现，使代码仍可编译，并对所有服务管理命令返回“仅 Windows 支持”的明确错误。不会在非 Windows 平台模拟服务管理。

## 启动与停止流程

无服务管理子命令时，Windows 入口首先判断进程是否处于交互式会话：

- SCM 启动：进入服务调度器，报告 `StartPending`，启动应用后报告 `Running`。
- 普通终端启动：沿用当前 SIGINT/SIGTERM 上下文和错误输出行为。
- `-validate`：保持现有离线校验，不进入 SCM 服务运行流程。

SCM 发出 `Stop` 或 `Shutdown` 时，服务执行器报告 `StopPending` 并取消传给现有 `run` 函数的上下文。`run` 继续按现有顺序关闭 HTTP 服务和设备采集任务。完成后报告 `Stopped`。应用启动失败或关闭失败时，将错误写入现有日志，并以非零服务退出码结束；不把配置内容或敏感连接信息写入 Windows 错误文本。

服务启动和停止等待使用有界超时及 SCM wait hint/checkpoint，避免管理命令无限等待。超时错误应包含操作和服务名称。

## 路径语义

Windows 服务的默认工作目录通常不等于程序目录，因此不能依赖当前工作目录。

- 安装时把配置文件路径规范化为绝对路径。
- 加载配置后，数据库和日志中的相对路径以配置文件所在目录为基准解析。
- 绝对数据库和日志路径保持不变。
- 控制台模式也采用相同规则，保证两种运行方式行为一致。

这会使示例配置 `configs/config.toml` 中的 `data/...` 与 `logs/...` 指向 `configs/data/...` 和 `configs/logs/...`。为保持当前仓库既有目录布局，示例配置同步改为相对于配置目录的 `../data/modbus-scan.db` 与 `../logs/modbus-scan.log`，README 明确说明此规则。

## 权限与错误处理

安装、卸载、启动、停止和重启通常需要管理员权限。程序不尝试绕过 UAC；权限不足时返回包含建议“请在管理员 PowerShell 中运行”的错误。`status` 在系统允许只读查询时不要求提升权限。

需要区分并清晰报告以下情况：

- 服务已存在或不存在。
- 服务已运行、已停止或处于过渡状态。
- 配置文件不存在或无效。
- SCM 访问被拒绝。
- 启停等待超时。
- 应用在服务模式下启动失败。

`start` 对已经运行的服务视为成功，`stop` 对已经停止的服务视为成功；`install` 和 `uninstall` 不做隐式覆盖或忽略，以避免误操作其他注册项。

## 测试

遵循测试驱动开发：先写失败测试并确认失败原因，再写最小实现。

平台无关测试覆盖：

- 顶层子命令识别和参数拒绝。
- 六个管理命令的分发。
- `restart` 的停止、等待、启动顺序及已停止分支。
- 配置路径绝对化和配置校验。
- 相对数据库、日志路径按配置文件目录解析。
- 服务管理错误的上下文包装。
- 原有控制台启动、取消和 CSV 校验行为不回归。

Windows 专属测试覆盖：

- SCM 配置包含固定名称、显示名、自动启动和绝对启动参数。
- Windows 状态到公开状态文本的映射。
- 停止/关机控制请求会取消应用上下文。
- 过渡状态轮询和超时。

常规自动测试不实际注册系统服务，避免要求管理员权限和污染开发机。最终人工验收在管理员 PowerShell 中使用临时构建产物，依次验证安装、自动启动配置、启动、状态、重启、停止、卸载，以及服务模式下数据库和日志路径。

## 完成标准

- 六个服务管理命令行为符合上述契约。
- 服务能由 SCM 启动，并响应停止和系统关机请求。
- 服务注册为自动启动，使用绝对 exe 与配置路径。
- 控制台模式和 CSV 校验无回归。
- 相对运行时路径不受 Windows 服务工作目录影响。
- 单元测试、`go test ./...`、`go vet ./...` 和 Windows 构建通过。
- README 与示例配置和实际行为一致。
