# 点位描述与列表交互设计

## 目标

扩展点位配置，使描述、可写状态和页面布局在 SQLite、JSON API、CSV 与管理页面之间保持一致；同时改善宽表格和点位编辑弹框的操作体验。

## 数据模型与兼容性

- `points` 表新增 `description TEXT NOT NULL DEFAULT ''`。
- 启动迁移以增量方式为已有数据库添加字段，现有点位的描述默认为空，不重建或清空数据。
- `model.Point` 新增 `Description string`，JSON 字段名为 `description`。
- `Writeable` 使用整数表示，只允许 `0` 或 `1`；JSON API 请求和响应均使用数值，不接受布尔值。
- 描述允许为空；去除首尾空白后最多 255 个字符。新增、编辑和 CSV 导入共享同一校验规则。
- 点位创建、读取、分页列表、更新和全量替换都持久化描述。
- 采集写入权限仅在 `Writeable == 1` 时成立。

## CSV 契约

CSV 严格使用以下八列表头，顺序不可改变：

```csv
TagName,RegType,Address,DataType,BitOffset,BitLen,Writeable,Description
```

- `Writeable` 只接受 `0` 或 `1`，导出也固定输出 `0` 或 `1`。
- `Description` 是必备列，但单元格可为空，最大长度 255 个字符。
- 原七列 CSV 不再接受；仓库示例、测试和使用文档同步更新。
- CSV 仍执行严格、原子导入，任意行错误时不替换数据库中的已有点位。

## 点位主列表

- 在 `TagName` 后增加“描述”列并支持既有列宽拖动与本地保存。
- “可写”列直接显示 `0` 或 `1`。
- 表格设置足够的最小宽度，由 `.table-scroll` 提供水平滚动条。
- 最右侧“操作”表头和所有操作单元格使用 `position: sticky; right: 0`，设置不透明背景、层级和左侧阴影，横向滚动时始终可见。
- 描述及其他文本继续进行 HTML 转义，防止用户输入作为页面标记执行。

## 添加与编辑弹框

字段布局如下：

1. `TagName` 单独一行。
2. “描述”单独一行，最大输入长度为 255。
3. “寄存器类型”单独一行。
4. “地址”和“数据类型”位于同一行的两列。
5. `BitOffset` 和 `BitLen` 位于同一行的两列。
6. “允许写入”文字在前、复选框在后；勾选映射为 `1`，未勾选映射为 `0`。
7. “取消”和“保存”位于底部同一行并靠弹框右侧排列。

窄屏下，两列字段自动改为单列，避免输入控件过窄。新增和编辑均读写描述字段。

## 验证

- CSV 测试覆盖八列表头、描述往返、描述超长以及 `Writeable` 非 `0/1`。
- 存储测试覆盖新库建表、旧库增量迁移，以及描述和可写值的 CRUD 往返。
- 服务/API 测试覆盖描述校验、数值型 `writeable` 和布尔值拒绝。
- Web 静态资源测试覆盖描述列、固定操作列标记、弹框双列布局和 `0/1` 映射。
- 最终运行 `gofmt`、`go test ./...`、`go vet ./...` 和构建验证。
