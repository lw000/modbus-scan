# 点位批量删除与实时值 WebSocket 设计

## 目标

在设备点位配置页增加当前页批量删除，调整点位表格的字段顺序和文案，并为单个点位提供基于 WebSocket 订阅的实时值弹窗与浏览器端实时曲线。

## 范围与约束

- “删除当前页”只删除当前筛选条件下、当前页面已经加载的点位，不删除其他页面或其他筛选结果。
- 删除操作必须二次确认，并明确显示将删除的点位数量。
- 实时曲线只保留弹窗打开期间收到的数据；关闭弹窗后清空，不在服务端或数据库保存历史序列。
- WebSocket 只向连接推送该连接已经订阅的设备和位号。
- 保留现有 HTTP `/api/v1/devices/:id/values` 接口，避免破坏现有调用方；点位弹窗改用 WebSocket。
- 不引入前端图表库，使用原生 Canvas 绘制曲线。

## 用户界面

### 点位表格

表格列顺序调整为：

1. TagName
2. 类型
3. 地址
4. 数据类型
5. 位
6. 读写
7. 描述
8. 实时值
9. 更新时间
10. 操作

原“可写”列改名为“读写”。`writeable == 1` 显示“读写”，否则显示“只读”。每行操作列在“编辑”和“删除”之外增加“实时值”按钮。

工具栏增加“删除当前页”危险操作按钮。当当前页为空或请求正在执行时按钮禁用。确认对话框显示当前页点位数量；成功后重新请求当前页。如果删除后当前页超过新的总页数，则退到最后一个有效页。

### 实时值弹窗

点击“实时值”打开模态弹窗，显示点位 TagName、描述、当前值、更新时间和连接状态。弹窗打开后创建 WebSocket 连接并订阅一个点位；服务端先返回当前快照，随后推送采集更新。

弹窗使用 Canvas 绘制最多 300 个本次会话采样点。数值直接绘制，布尔值转换为 `0` 和 `1`；字符串、空值、NaN 或无穷值只更新文本，不写入曲线。关闭弹窗时取消订阅、关闭连接并清空样本。

连接意外断开时，弹窗显示断开状态，并采用有上限的退避重连；弹窗关闭后停止重连。重连成功后重新发送订阅，服务端再次推送当前快照。

## 批量删除 API

新增接口：

```text
DELETE /api/v1/devices/:id/points
Content-Type: application/json

{"ids":[11,12,13]}
```

成功响应：

```json
{"data":{"deleted":3}}
```

约束：

- `ids` 必填，数量为 1 到 500，元素必须为正整数且不得重复。
- 数据层在一个事务中验证所有 ID 都属于路径指定的设备。
- 只要有一个 ID 不属于该设备或不存在，整个请求失败，不删除任何点位。
- 删除成功后只递增一次设备 `config_version`。
- 单点删除接口保持不变。

前端提交的是当前 `page.items` 中的 ID，因此删除范围与用户看到的当前页严格一致，不根据过滤条件在服务端重新查询。

## WebSocket 协议

端点：

```text
GET /api/v1/ws
```

客户端订阅消息：

```json
{"action":"subscribe","device_id":1,"tags":["TagA"]}
```

客户端取消订阅消息：

```json
{"action":"unsubscribe","device_id":1,"tags":["TagA"]}
```

服务端值消息：

```json
{
  "type":"value",
  "device_id":1,
  "tag_name":"TagA",
  "value":12.5,
  "updated_at":"2026-09-21T10:00:00Z"
}
```

服务端错误消息：

```json
{"type":"error","code":"invalid_subscription","message":"订阅参数无效"}
```

每个连接最多订阅 500 个位号，客户端消息设置较小的读取上限。服务端仅接受同源浏览器连接。未知 action、非法设备 ID、空位号、过多位号或格式错误返回协议错误；无法继续安全处理时关闭连接。

订阅成功后，服务端从运行时管理器读取该设备当前快照，只向该连接发送订阅位号中已有的当前值。不存在的位号不会产生伪造值；后续只有采集器实际更新时才推送。

## 服务端架构与数据流

新增独立的实时值 Hub，职责仅包括：连接注册、订阅索引、取消订阅和按 `device_id + tag_name` 分发值事件。Hub 不持久化历史曲线。

运行时边界增加值事件发布能力。采集器每次成功解析并更新 UDM 后，通过非阻塞回调发布包含设备 ID、TagName、值和采集时间的事件。主程序把运行时事件源与 WebSocket Hub 连接起来。

数据流如下：

```text
Modbus scan -> UDM update -> runtime value event -> WebSocket Hub
                                               -> matching subscribers only
                                               -> browser text and Canvas chart
```

Hub 为每个 WebSocket 连接使用有界发送队列。采集循环不得等待网络写入；连接队列满时关闭该慢连接，使其通过前端重连恢复。每个连接只有一个读取协程和一个写入协程，写入协程负责 JSON、ping 和写超时，避免并发写 WebSocket。

HTTP 服务关闭会取消 Hub 上下文并关闭所有连接。连接断开时必须移除其全部订阅，避免泄漏索引。

## 依赖选择

Go 标准库不提供 WebSocket 服务端升级与帧处理。新增一个维护成熟、API 较小的 WebSocket 依赖，并锁定到 `go.mod`/`go.sum`。不新增其他后端框架或前端依赖。

## 错误处理

- 批量删除沿用现有 JSON 错误结构，非法请求返回 400，点位不存在或归属不符返回 404，数据库错误返回安全的 500 响应并记录详细日志。
- WebSocket 升级失败交给 HTTP 错误路径；升级后的协议错误使用错误消息和合适的关闭码。
- WebSocket 消息、日志和错误中不包含连接串或其他敏感配置。
- 采集事件发布失败或没有订阅者不影响 UDM 更新和下一轮采集。

## 测试与验收

后端测试覆盖：

- 批量删除成功、空列表、重复 ID、超过 500 个 ID、跨设备 ID、缺失 ID，以及失败时事务不产生部分删除。
- 成功批量删除只增加一次设备配置版本。
- Hub 只向匹配 `device_id + tag_name` 的连接推送，取消订阅后停止推送。
- 新订阅收到已有当前快照，不存在的位号不产生值消息。
- 慢连接不会阻塞事件发布，断开后订阅被清理。
- WebSocket 非法消息、订阅上限、连接关闭和服务停止行为。
- 采集器成功更新 UDM 时发布带设备 ID 和时间戳的值事件。

前端静态资源测试至少验证批量删除按钮、实时值按钮、弹窗、Canvas、列顺序和“读写”文案存在。人工验收包括筛选分页后的当前页删除、弹窗开关、数值和布尔曲线、断线重连，以及多个浏览器分别订阅不同位号时不会收到彼此的数据。

最终运行 `gofmt`、`go test ./...` 和 `go vet ./...`；涉及 Hub 和运行时共享状态，额外运行 `go test -race ./...`。

## 兼容性

现有设备、点位 CRUD、CSV 导入导出、分页参数和 `/values` HTTP 接口保持兼容。新增批量删除接口和 WebSocket 端点，不修改 SQLite schema。点位配置变化仍需按现有机制重启设备后由采集运行实例加载。
