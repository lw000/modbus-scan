# Kafka 表单布局与全量周期默认值设计

## 目标

优化 Kafka 配置界面的信息密度和控件对齐方式，并将新建设备的全量推送周期默认值调整为 1 秒。

## 页面布局

### 全局 Kafka 设置

- Kafka 设置表单在桌面宽度下使用两列布局。
- “启用”文字与复选框在同一行显示。
- 其他配置项按照现有顺序依次填入两列。
- 状态、错误信息、标题和操作按钮保持整行显示。
- 窄屏下自动回退为单列，避免输入框过窄。

### 设备 Kafka 推送

- “启用”文字与复选框在同一行显示。
- “推送模式”标题、变化推送和全量推送两个单选项在同一行显示。
- Topic 与全量周期使用现有表单风格排列。
- 变化模式下继续禁用全量周期输入框；切换到全量模式后可修改。
- 保存行为和接口协议不变。

## 全量周期默认值

- 新建设备对应的 `device_kafka_configs.full_interval_sec` 默认值从 60 秒改为 1 秒。
- 页面中尚未加载设备配置时的静态输入默认值同步改为 1 秒。
- 已有设备保存在 SQLite 中的周期值不迁移、不覆盖，保证用户现有配置不变。
- 合法范围继续保持 1 到 86400 秒。

## 实现方式

复用现有 `.form-row.two-columns` 响应式网格，并增加少量 Kafka 表单专用类，用于整行元素、同行复选框以及同行单选组。数据库迁移定义只修改新建设备配置行的默认插入值，不执行已有数据更新。

## 测试与验证

- 扩展内嵌 Web 资源测试，断言两个 Kafka 表单包含所需布局类及 1 秒静态默认值。
- 更新存储层测试，断言新建设备的 Kafka 全量周期默认值为 1 秒。
- 运行 `go test ./...`。
- 运行 `go test -race ./...`，确认页面资源和默认值修改未影响并发相关功能。
- 运行 `go vet ./...`。

## 非目标

- 不修改 Kafka 消息格式、发送逻辑或模式互斥规则。
- 不迁移已有设备的周期配置。
- 不修改 Kafka 管理 API 的字段或响应结构。
